# Modo: proyecto — Evaluación de Proyecto para Portfolio

Cuando el usuario quiere evaluar si vale la pena construir un proyecto para su portfolio o si un proyecto existente es relevante para su búsqueda.

## Inputs necesarios

- Idea del proyecto o descripción
- Tecnologías involucradas
- Tiempo estimado de desarrollo
- Objetivo (aprender, demostrar, conseguir trabajo, etc.)

## Evaluación

### Bloque A — Relevancia para Búsqueda Laboral

- ¿Qué arquetipos/roles valorarían este proyecto?
- ¿Demuestra skills que están en demanda en el mercado argentino actual?
- ¿Resuelve un problema real o es un proyecto "de juguete"?

### Bloque B — Análisis Técnico

- Stack propuesto y su vigencia en el mercado
- Complejidad y profundidad técnica
- ¿Demuestra diseño de sistemas o solo implementación?

### Bloque C — Diferenciación

- ¿Qué hace único a este proyecto vs otros portfolios?
- ¿Tiene potencial para generar tracción (estrellas GitHub, usuarios, etc.)?
- ¿Se puede cuantificar el impacto?

### Bloque D — Plan de Ejecución

- Fases y milestones
- MVP mínimo para mostrar en 2 semanas
- Estrategia de documentación y presentación

### Bloque E — Veredicto

- **Hacelo ya** — alto impacto, baja inversión
- **Hacelo si...** — condicional
- **No lo hagas** — baja diferenciación, mejor invertir el tiempo en otra cosa
- **Modificalo** — la idea es buena pero necesita ajustes

## Consideraciones para Argentina

- Proyectos que resuelven problemas locales tienen más impacto en entrevistas con empresas argentinas
- Si apuntás a contractor USD, priorizá proyectos con visibilidad internacional (inglés, documentación, deploy público)
- La comunidad tech argentina valora proyectos con impacto social o utilidad pública
